# Data Policy

## 1. Purpose

이 문서는 실험플랫폼에서 수집하는 데이터의 `범위`, `보관 기간`, `접근 권한`, `품질 기준`을 정의한다.

데이터 정책의 핵심 원칙은 아래와 같다.

- 필요한 데이터만 수집한다.
- 수집 목적과 사용 범위를 사전에 정의한다.
- 데이터 품질 기준은 실험 설계 전에 고정한다.
- 개인 식별 정보와 분석용 데이터를 분리한다.

---

## 2. 수집 범위 정책

### 수집 대상

`DATA_SCHEMA.md`에 정의된 엔터티를 기준으로 수집한다.

- Cohort 메타데이터
- Participant 행동 데이터 (참여, 출석, 완주 여부)
- Weekly Activity 데이터 (출석, 발표, 피드백, 상호작용)
- Operational Load 데이터 (운영 부담 지표)

### 수집 제한

아래 데이터는 분석 목적으로 수집하지 않는다.

- 실험 목적과 무관한 개인 신상 정보
- 참여자가 명시적으로 제공하지 않은 외부 행동 데이터
- 운영상 불필요한 고빈도 로그 (저장 비용 대비 분석 가치가 낮은 것)

---

## 3. 보관 기간 정책

| 데이터 유형 | 보관 기간 | 근거 |
| --- | --- | --- |
| Cohort 메타데이터 | 무기한 | 장기 cohort 비교를 위한 기준값 |
| Participant 행동 데이터 | 무기한 | 재참여율, 장기 retention 분석 필요 |
| Weekly Activity 데이터 | 최소 3년 | 충분한 기수 누적 확보 |
| Operational Load 데이터 | 최소 2년 | 운영 부담 추세 분석 |
| 실험 결과 기록 | 무기한 | 학습 축적 정책과 연동 |

보관 기간 만료 전 삭제가 필요한 경우 사전에 이유를 기록한다.

---

## 4. 접근 권한 정책

### 접근 등급

| 등급 | 접근 가능 데이터 | 대상 |
| --- | --- | --- |
| Level 1 | 집계 결과만 (개인 비식별) | 결과 공유 대상 전체 |
| Level 2 | 개인 단위 행동 데이터 | 실험 오너, 분석 담당자 |
| Level 3 | 전체 원본 데이터 + 운영 부담 | 플랫폼 관리자 |

### 접근 원칙

- 분석에 필요한 최소 수준의 권한만 부여한다.
- 개인 식별 정보(이름, 연락처 등)는 분석 데이터와 분리 보관한다.
- 분석 결과 공유 시 개인 식별이 가능한 형태로 공유하지 않는다.

## 5. 데이터 품질 기준

`DATA_SCHEMA.md`의 Data Quality Rules를 기준으로 하되, 아래를 추가로 적용한다.

### 수집 시점 기준

- 이벤트 타임스탬프는 단일 기준 시간대(KST 또는 UTC)로 통일한다.
- 기준 시간대를 변경할 경우 변경 시점과 사유를 기록한다.

### 결측값 처리 기준

- `completed_flag` 결측 → 미완주로 처리, 단 사유 기록 필수
- `attended_flag` 결측 → 해당 주차 미출석으로 처리
- `week_number` 결측 → 해당 레코드 분석 제외 후 기록

### 이상값 기준

- 동일 participant의 동일 week_number 중복 레코드 → 최신 기록 우선, 원본 보존
- cohort 내 `first_attended_at`이 `start_date` 이전인 경우 → 데이터 오류로 플래그

### 분석 전 품질 체크 항목

실험 분석 시작 전 아래를 확인한다.

- [ ] 분모 집합(첫 참여 인원) 확정 여부
- [ ] `completed_flag` 정의가 운영 기준과 일치하는지
- [ ] cohort 간 `week_number` 기준이 동일한지
- [ ] 결측 및 이상값 처리 결과 기록 여부

## 6. CUPED용 선행 데이터 보관

CUPED 적용을 위한 공변량 데이터는 별도로 보관한다.

- `prior_attendance_rate`: 이전 기수 출석률
- `preprogram_activity_score`: 프로그램 시작 전 활동 점수
- `application_engagement_score`: 신청서 기반 참여 의지 프록시
- `week1_intensity_score`: 첫 주 참여 강도

이 데이터는 outcome과 상관 여부를 먼저 검증한 뒤 사용한다. 검증 결과도 함께 보관한다.

# Experiment Framework

## 1. What This Project Is

이 프로젝트의 이상적 실험 구조는 `동시점 무작위 배정` 기반의 랜덤 A/B 테스트다.
하지만 현재 운영 환경에서는 동일 시점 무작위 배정이 어렵기 때문에, 실제 적용은 `기수 단위 cohort 비교 실험`을 기본으로 한다.

따라서 `10기 vs 11기` 같은 비교는 엄밀한 의미의 A/B 테스트가 아니라 다음처럼 해석한다.

- 이상적 방법: randomized A/B test
- 현실 적용: cohort-based comparative experiment
- 분석 분류: quasi-experiment
- 해석 주의: 기수 구성 차이, 시즌성, 운영자 개입 차이, 외부 일정 영향 통제 필요

**주요 교란 요인 (confounders) 목록:**
- 모집 시기/채널 차이 → 신청자 풀 구성 자체가 다를 수 있음
- 운영자(멘토) 차이 → 개인 역량 차이가 효과를 만들 수 있음
- 계절/외부 이벤트 효과 → 특정 시기의 외부 요인이 참여율에 영향
- 커리큘럼/자료 자연 개선 → 시간이 지날수록 운영 품질이 올라가는 효과

이 교란 요인들은 실험 변경사항의 효과와 구분되지 않을 수 있으므로, cohort 비교 결과는 항상 인과 주장이 아닌 **운영 참고 근거**로만 해석한다.

## 2. Core Flow

핵심 분석 흐름은 아래 순서를 따른다.

`North Star Metric 정의 -> Funnel로 병목 파악 -> Retention으로 지속성 확인 -> Cohort 비교로 효과 추정 -> Bayesian 기반 의사결정`

## 3. North Star Metric

North Star Metric은 `완주율` 하나로 둔다.

다만 완주율은 반드시 명시적 정의를 먼저 고정해야 한다. 권장 기본 정의는 아래와 같다.

`완주율 = 최종 제출 완료 인원 / 첫 참여 인원`

이 문서에서는 `첫 참여자 기준 완주율`을 기본 정의로 사용한다. 이유는 신청자 기준보다 운영 잡음이 적고, 실제 학습 시작자 기준보다 추적 일관성이 높기 때문이다.

완주율 해석 시 아래 세 기준은 혼용하지 않는다.

- 신청자 기준 완주율
- 첫 참여자 기준 완주율
- 실제 학습 시작자 기준 완주율

## 4. Funnel vs Retention

둘은 함께 봐야 하지만, 정의는 분리한다.

### Funnel

Funnel은 `어디서 꺾이는가`를 본다. 즉 단계 전환을 본다.

권장 단계는 아래와 같다.

- 신청
- 승인
- 첫 참여
- 1주차 출석
- 최종 완주

### Retention

Retention은 `얼마나 오래 남는가`를 본다. 즉 시간 경과에 따른 유지율을 본다.

권장 지표는 아래와 같다.

- 1주차 이후 잔존율
- 2주차 생존율
- 3주차 생존율
- 4주차 생존율
- 다음 기수 재참여율

## 5. Guardrail Metrics

Primary metric은 완주율이지만, 실험 평가는 Guardrail을 함께 봐야 한다.

권장 Guardrail은 아래와 같다.

- 중도 이탈률
- 주차별 출석률
- 운영 부담 지표

운영 부담 지표는 예를 들어 아래 값을 사용할 수 있다.

- 멘토 개입 시간
- 운영 메시지/리마인드 횟수
- 운영자 수동 처리 건수

완주율이 상승하더라도 Guardrail이 악화되면 실험안은 보류할 수 있다.

## 6. Correlation and Leading Indicators

발표 횟수, 댓글 수, 피드백 수 같은 활동성 변수는 `완주의 선행 신호`를 탐색하는 데 유용하다.

다만 이 영역은 기본적으로 `상관 분석` 또는 `예측 지표 탐색`으로 정의한다.

- 목적: 완주의 leading indicator 후보 탐색
- 주의: 인과 해석 금지

예를 들어 `발표 횟수가 높을수록 완주율이 높다`는 결과는 유용한 운영 신호일 수 있지만, 발표가 완주를 유발한다고 바로 해석하지 않는다.

## 7. Collaboration Metrics

협업 수는 장기적으로 네트워크 분석으로 확장할 수 있지만, MVP 단계에서는 측정 비용이 낮은 상호작용 지표부터 시작한다.

우선 수집 권장 항목은 아래와 같다.

- 댓글 수
- 피드백 횟수
- 공동 작업 횟수
- 멘토/동료 interaction 수

표현은 아래처럼 둔다.

`협업 수 -> interaction 분석 -> 향후 network 분석 확장`

## 8. Bayesian as a Decision Tool

Bayesian 분석은 단순히 `직관적인 해석 방법`으로만 설명하지 않고, 실제 운영 의사결정 규칙과 함께 써야 한다.

예시 기준은 아래와 같다.

- `P(B > A) > 80%`: 채택 검토 시작
- `P(B > A) > 95%`: 강한 채택 신호
- uplift가 양수여도 guardrail 악화 시 보류

**주의: 위 임계값(80%, 95%)은 관례적 기본값이다.** 수학적으로 도출된 값이 아니며, false positive 비용과 false negative 비용의 상대적 크기에 따라 달라져야 한다. 실데이터가 쌓이면 프로그램 맥락에 맞게 보정한다.

권장 판단 프레임은 다음 세 조건을 함께 본다.

- Primary metric 개선 확률
- Guardrail 악화 확률
- 최소 효과 크기

예시 규칙:

- Primary metric 개선 확률 85% 이상
- Guardrail 악화 확률 20% 미만
- 최소 효과 크기 +5%p 이상

## 9. Sequential Testing

Sequential Testing은 `매주 본다`가 아니라 `멈추는 기준까지 포함한 운영 규칙`으로 정의해야 한다.

**주의: 여기서 사용하는 방식은 엄밀한 Sequential Testing이 아니다.** 진짜 Sequential Testing은 alpha-spending function(Pocock, O'Brien-Fleming 등)이나 mSPRT 같은 오류율 제어 절차를 요구한다. 해당 절차 없이 매주 결과를 확인하면 다중 비교(multiple testing) 문제가 발생한다. 이 프로젝트에서는 운영 편의를 위한 **근사적 stopping rule**로만 사용하며, 통계적으로 엄밀한 Sequential Testing과 동일하게 해석하지 않는다.

반드시 필요한 항목은 아래와 같다.

- 최소 관측 기간
- 최소 샘플 수
- 조기 종료 조건
- 보류 조건

예시:

- 최소 2주 운영 전 조기 종료 금지
- 누적 참여자 50명 미만이면 판단 보류
- `P(B > A) > 95%` 이고 Guardrail 안정 시 조기 채택
- 악화 확률이 높으면 조기 중단 검토

## 10. CUPED Usage Condition

CUPED는 유용하지만 선행조건이 있을 때만 사용한다.

필요 조건은 아래와 같다.

- 실험 전 공변량이 존재해야 함
- 해당 값이 outcome과 상관이 있어야 함
- 측정 신뢰도가 확보되어야 함

현재 운영 환경에서 가능한 후보는 아래와 같다.

- 이전 출석률
- 사전 활동 점수
- 신청서 기반 engagement proxy
- 첫 주 참여 강도

권장 표현:

`CUPED는 과거 참여 데이터가 충분히 있을 때 분산 감소용으로 활용한다.`

## 11. Practical Summary

이 문서의 핵심은 다음과 같다.

- 현재 실무 적용은 랜덤 A/B보다 기수 기반 quasi-experiment에 가깝다.
- North Star는 완주율 하나로 두되 정의를 엄밀히 고정한다.
- Funnel은 병목, Retention은 지속성을 본다.
- Bayesian은 설명용 통계가 아니라 의사결정 규칙과 함께 사용한다.
- Correlation은 선행 신호 탐색용이며 인과 추론으로 확장하지 않는다.
- Sequential Testing과 CUPED는 적용 조건을 명시한 뒤 보조적으로 사용한다.

# Result Policy

## 1. Purpose

이 문서는 실험이 종료된 이후 결과를 `언제`, `어떻게`, `누구에게` 공유하고, `어떤 절차로` 운영에 반영하는지를 정의한다.

결과 활용의 핵심 원칙은 아래와 같다.

- 결과는 반드시 기록되어야 한다.
- 결과 공유는 해석 강도를 명시한 채로 이루어진다.
- 채택/보류/중단 모두 동등하게 기록한다.
- 실패한 실험도 학습 자산이다.

---

## 2. 결과 공유 시점

| 시점 | 공유 대상 | 내용 |
| --- | --- | --- |
| 실험 종료 직후 | 실험 오너 | 1차 분석 결과 초안 |
| 의사결정 확정 후 | 운영팀 전체 | 최종 결과 + 결정 상태 + 반영 계획 |
| 다음 기수 시작 전 | 관련 운영자 | 이전 실험 결과 요약 + 적용 여부 |

---

## 3. 결과 공유 형식

결과를 공유할 때 아래 항목을 반드시 포함한다.

### 필수 포함 항목

- 실험명 및 cohort_id
- 변경사항 요약 (Treatment 설명)
- Primary Metric 결과 (완주율 변화, P(B > A))
- Guardrail 결과 (이상 여부)
- 최종 결정 상태: `ship` / `hold` / `rollback` / `need_more_data`
- 결정 근거 (한 문장 이상)
- 다음 기수 반영 여부

### 해석 강도 명시 의무

공유 시 아래 중 하나를 반드시 표시한다.

- `randomized A/B`: 무작위 배정 기반, 인과 해석 가능
- `cohort comparison`: 기수 비교 기반, 운영 참고 근사치
- `exploratory`: 표본 부족 또는 조건 미충족, 방향성 참고 수준

cohort comparison 결과를 인과적으로 서술하지 않는다.

---

## 4. 의사결정 반영 절차

### Ship

- 다음 기수 운영에 해당 변경사항을 기본으로 포함한다.
- `EXPERIMENT_POLICY_BASE.md`의 학습 축적 항목에 기록한다.
- 동일 실험은 재등록하지 않는다.

### Hold

- 불확실 요인과 재실험 조건을 명시하고 기록한다.
- 다음 기수에서 동일 조건으로 재관찰하거나 조건을 개선한 뒤 재등록한다.

### Rollback

- 변경사항을 제거하고 이전 운영 방식으로 복귀한다.
- 어떤 지표가 어떻게 악화되었는지 구체적으로 기록한다.
- 향후 유사한 변경 시 참고할 수 있도록 보관한다.

### Need More Data

- 동일 실험을 다음 기수에서 연장 관찰한다.
- 부족한 조건(기간, 샘플 수, cohort 구성 차이 등)을 명시한다.

---

## 5. 결과 기록 보관 정책

- 모든 실험 결과는 종료 후 삭제하지 않는다.
- 결과는 DB 메타데이터 또는 문서 형태로 누적 보관한다.
- 실패/보류 실험도 동일한 형식으로 보관한다.

### 보관 필수 항목

- `experiment_id`
- `decision_status`
- `decision_reason`
- `primary_metric_result`
- `guardrail_result`
- `interpretation_type` (randomized / cohort / exploratory)
- `next_action`
- `recorded_at`

---

## 6. 결과 재해석 금지 원칙

결과가 나온 이후 아래 행동은 금지한다.

- 결정이 확정된 후 유리한 지표만 선택해 재보고
- Primary Metric 결과가 나쁠 때 Supporting KPI를 내세워 채택 주장
- 결정 상태를 기록 없이 변경

단, 새로운 데이터나 운영 맥락이 추가된 경우 재검토는 가능하며, 이 경우 재검토 이유와 변경 전후를 모두 기록한다.

# Community Benchmarks

## 1. Purpose

이 문서는 `abtest` 프로젝트의 지표 설계와 실험 운영 원칙을 보강하기 위해, 다른 커뮤니티와 학습 플랫폼이 데이터를 어떻게 활용했는지 참고 사례를 정리한 문서다.

중요한 목적은 사례를 그대로 복제하는 것이 아니라, 각 플랫폼이 `활동`, `성과`, `초기 경험`, `관계`, `유지`를 어떤 방식으로 측정했는지 보고 우리 상황에 맞는 설계 원칙으로 번역하는 데 있다.

## 2. Benchmark Table

| 커뮤니티 | 데이터 유형 | 핵심 활용 방식 | 실험/분석 방법 | 핵심 지표 | 우리에게 적용 |
| --- | --- | --- | --- | --- | --- |
| Hacker News | 투표, 클릭, 댓글 | 랭킹 알고리즘 개선 | A/B 테스트 | CTR, vote rate | 노출 대비 참여율 |
| Reddit | 업보트, 구독, 작성자 | 추천 시스템 최적화 | ML, 클러스터 분석 | retention, engagement | 사람 중심 분석 |
| Stack Overflow | 질문, 답변, 채택 | 문제 해결 최적화 | 태그 추천 실험 | 채택률, 응답 시간 | 결과 기반 KPI |
| Kaggle | 참여, 노트북, 순위 | 참여 유도 시스템 | 랭킹 실험 | 참여율, 완주율 | 프로젝트 완주 |
| freeCodeCamp | 학습, 포럼 | 학습 경로 개선 | A/B 테스트 | 완료율, dropout | 학습 흐름 분석 |
| Wikipedia | edit, revert | 기여 유지 | cohort 분석 | survival rate | 첫 경험 최적화 |
| Discord / Slack | 메시지, 반응 | 활성도 분석 | 네트워크 분석 | active ratio | lurker 분석 |
| MOOC | 강의, 과제 | dropout 분석 | funnel 분석 | retention curve | 주차별 유지율 |
| GitHub | PR, commit, review | 협업 최적화 | 그래프 분석 | merge율, 협업도 | 협업 구조 분석 |

## 3. Detailed Cases

### Hacker News / Reddit

핵심 포인트는 단순 upvote 수가 아니라 `노출 위치`, `초기 반응`, `시간`, `사회적 편향`까지 함께 봐야 한다는 점이다.

- raw 인기 지표는 왜곡될 수 있다.
- 초기 노출이 결과를 과대 증폭할 수 있다.
- 인기와 실제 품질은 같지 않을 수 있다.

우리에게 주는 교훈은 아래와 같다.

- `좋아요 수`, `댓글 수`를 그대로 성과로 보지 않는다.
- 가능하면 노출 대비 반응률, 시간 보정 점수 같은 보정 지표를 본다.
- 활동량보다 `기회 대비 반응`을 보는 구조가 더 안정적이다.

### Reddit

참여 예측에서는 콘텐츠 자체보다 `누가 올렸는지`, `어느 커뮤니티 맥락인지`가 더 중요하게 작동하는 경우가 많다.

우리에게 주는 교훈은 아래와 같다.

- 콘텐츠 중심 설계만으로는 부족하다.
- contributor 특성, 기존 참여 이력, 소속 그룹 같은 맥락 데이터를 함께 봐야 한다.
- `좋은 글`보다 `좋은 사람 + 좋은 맥락`이 더 설명력이 있을 수 있다.

### Stack Overflow

Stack Overflow는 활동량보다 `문제 해결 성공 여부`를 데이터 구조의 중심에 둔다.

핵심 구조:

- 질문
- 답변
- 채택 여부
- 평판

우리에게 주는 교훈은 아래와 같다.

- 활동량 중심 KPI는 약하다.
- `무엇이 해결되었는가` 같은 outcome metric이 핵심이다.
- 커뮤니티 활동은 `결과를 만들어냈는가`와 연결되어야 한다.

### Kaggle

Kaggle은 참여 데이터를 `성과`, `완주`, `재참여`와 연결한다.

우리에게 주는 교훈은 아래와 같다.

- 단순 참여 수보다 성과 기반 참여를 본다.
- leaderboard, 결과물 제출, 재참여 여부처럼 결과가 남는 지표가 중요하다.
- 커뮤니티는 `학습 + 실전 문제 해결` 구조로 해석할 수 있다.

### freeCodeCamp

학습 커뮤니티에서는 완료율만으로 충분하지 않고, `이탈 지점`과 `반복 학습 흐름`을 함께 봐야 한다.

우리에게 주는 교훈은 아래와 같다.

- 완주율 하나로는 운영 개선 포인트가 보이지 않는다.
- dropout이 발생하는 단계와 주차를 분석해야 한다.
- Funnel과 Retention을 함께 봐야 학습 경로를 개선할 수 있다.

### Wikipedia

Wikipedia는 신규 기여자의 첫 경험이 생존율에 큰 영향을 준다는 점을 잘 보여준다.

우리에게 주는 교훈은 아래와 같다.

- onboarding 경험이 retention의 핵심이다.
- 첫 행동 직후의 피드백 경험을 별도로 측정해야 한다.
- `첫 참여 후 7일`, `첫 발표 후 반응`, `첫 피드백 경험` 같은 지표가 중요하다.

### Discord / Slack

메시지 수가 많은 것이 곧 건강한 커뮤니티를 뜻하지는 않는다. 실제로는 소수 헤비 유저가 대부분의 활동을 만드는 경우가 많다.

우리에게 주는 교훈은 아래와 같다.

- 총 메시지 수만 보면 활성도 착시가 생긴다.
- active user ratio가 중요하다.
- lurker가 contributor로 전환되는 흐름을 별도로 봐야 한다.

### MOOCs

MOOC 플랫폼은 대부분의 이탈이 초반 1~2주에 집중된다는 점을 바탕으로, 주차별 유지 곡선을 핵심 분석 도구로 사용한다.

우리에게 주는 교훈은 아래와 같다.

- 전체 완주율보다 주차별 생존곡선이 더 많은 운영 인사이트를 준다.
- 과제 제출 여부, 첫 주 활동 강도는 early warning signal이 될 수 있다.
- 초반 이탈 방지 장치가 전체 성과를 크게 바꾼다.

### GitHub

GitHub는 단순 commit 수보다 `PR merge`, `review`, `협업 네트워크`를 더 중요한 협업 데이터로 다룬다.

우리에게 주는 교훈은 아래와 같다.

- 개인 활동량보다 협업 구조가 더 중요할 수 있다.
- 리뷰 참여, 공동 작업, 연결 구조를 장기적으로 봐야 한다.
- 초기에는 interaction 기반으로 시작하고, 데이터가 쌓이면 네트워크 분석으로 확장한다.

## 4. Shared Patterns

겉보기에는 플랫폼별 구조가 달라 보여도, 데이터 활용 방식에는 공통 패턴이 있다.

### 1. 단순 활동 데이터는 거의 무의미하다

- 글 수
- 댓글 수
- 접속 수

이 값들은 참고는 되지만, 단독 KPI로 쓰기에는 약하다.

### 2. 결과 데이터가 핵심이다

- Stack Overflow: 해결되었는가
- Kaggle: 성과가 났는가
- freeCodeCamp: 완료했는가

공통 메시지는 `Outcome metric이 핵심`이라는 점이다.

### 3. 초기 경험이 retention을 결정한다

- Wikipedia: 첫 edit
- MOOC: 첫 주차
- Reddit: 첫 포스트

우리에게도 `first session`, `first action`, `first feedback` 분석이 필수다.

### 4. 사람은 콘텐츠만큼 중요하다

누가 참여했는지, 어떤 그룹 맥락인지, 기존 관계가 있는지가 결과에 큰 영향을 준다.

### 5. 네트워크 효과가 중요하다

협업, 그룹, 태그, 서브커뮤니티 구조는 유지와 성과에 영향을 준다.

## 5. Expanded Framework for Our Community

다른 사례를 바탕으로 우리 커뮤니티의 분석 프레임은 아래 다섯 축으로 확장할 수 있다.

| 카테고리 | 측정해야 할 것 |
| --- | --- |
| 활동 | 출석, 글, 댓글 |
| 결과 | 프로젝트 완주, 결과물 |
| 성장 | skill 변화, 기여 수준 |
| 관계 | 협업 네트워크 |
| 초기 경험 | 첫 참여 후 7일 유지 |
| 기여 전환 | lurker -> contributor 전환 |

## 6. Most Important Conclusion

좋은 커뮤니티는 `활동`이 아니라 `변화`를 측정한다.

- Reddit: 참여 변화
- Stack Overflow: 문제 해결
- Kaggle: 실력 향상과 성과
- freeCodeCamp: 학습 완료

우리도 단순 활동 로그보다 아래를 더 중요하게 봐야 한다.

- 참여자가 실제로 남았는가
- 결과물을 만들었는가
- 다음 기수에 다시 오는가
- 기여 수준이 올라갔는가

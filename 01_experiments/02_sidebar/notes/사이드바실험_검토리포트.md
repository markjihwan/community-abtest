## 0. TL;DR (3줄)

1. 설계 문서는 잘 구성됨(분모=노출, SRM 게이트, Guardrail-first, 탐색 분류) — playbook과 정합.
2. 그러나 실측 결과, 설계가 전제한 계측 인프라와 실제 파이프라인이 **구조적으로 3곳 어긋남**: `experiment_id` 전 행 null → 설계 쿼리 0행, `session_id` 사실상 부재 → Guardrail·세션 dedup 계산 불가, 노출은 `event_log`가 아니라 `dl_feature_flag_exposure`(flag_key 기준)에 적재.
3. 실험은 등록만 된 상태(**status=draft, flag 미연결**). 배포 전에 계측 계약 4건을 실제 SDK와 맞추고 SNAV-14 QA 게이트를 통과해야 함(§6).

## 2. 잘 구성된 부분 (유지)

- **분모 = `exp_exposure`(노출) 고정, 배정-only 제외** — 회고 실험의 생존자 편향 교훈 반영. K님 명세(§1 "분모는 노출이지 배정이 아님")와 일치.
- **SRM 선행 게이트(T0)** — 미통과 시 어떤 판정도 내리지 않음. `srm_check.py` 검증 완료.
- **Guardrail-first + 4-state 판정** — playbook 3-6 그대로.
- **표본 게이트 정직 분류** — MAU 500 < 필요 n 377~3,397 → 탐색 실험. ship 단정 금지 명시.
- 문서 분리(spec/분석계획/데이터정의/백로그)와 상호 링크, "명세까지만 완료·미완 정직 표기" 원칙 준수.

## 3. 구조적 불일치 — 치명 (이대로면 분석 불가)

### 3-1. `queries.md`의 `experiment_id` 필터는 현재 파이프라인에서 0행

설계 쿼리 S1~S3 전부 `WHERE experiment_id='sidebar-nav-v1'` 전제. 실측: `dl_event_log.experiment_id`는 **전 행(432/432) null** — 현 SDK는 event_name으로만 이벤트를 식별한다.
→ **대응**: SDK가 experiment_id를 채우도록 수정 확약을 받거나, 쿼리를 event_name(+flag_key) 기준으로 개정.

### 3-2. `session_id` 부재 — Guardrail 2종은 계산 자체가 불가능

설계의 세 기둥이 모두 session_id 의존: ① 세션당 1회 노출 dedup ② 클릭-노출 variant 짝 검증 ③ Guardrail(홈 이탈률·첫방문 세션시간 — 전부 세션 단위 지표).
실측: 회고 이벤트 session_id 231/231 null(7/2 재배포 이후에도 미수정 — 개발팀 누락 인정, round1 노트), 노출 테이블(`dl_feature_flag_exposure`)엔 컬럼도 없음.
→ **이 상태로 시작하면 Guardrail을 계산할 수 없어 playbook상 ship 판정이 원천 불가능한 실험이 된다.** SNAV-14(계측 QA)의 최우선 항목으로 승격 필요.

### 3-3. 노출 분모의 소스 테이블이 설계와 다름

설계: `event_log.exp_exposure` 단일 소스. 실제: `decide()` 노출(impression)은 `dl_feature_flag_exposure`에 flag_key 기준 적재.
→ **대응**: 분모·SRM은 `dl_feature_flag_exposure`, 퍼널·클릭·전환은 `event_log`로 역할을 나눠 data-definition에 못박거나, 노출을 event_log에도 이중 적재하도록 결정. 두 소스 간 유저 수 대사(reconciliation) 검증 항목 추가.

## 4. 구조적 불일치 — 중요

4. **UTC/KST 경계**: `base_date`가 UTC 기준(실측 §1). 설계 쿼리의 `base_date >= '2026-06-28'` 필터와 `base_date=occurred_at::date` 정의에 **시간대 명시 없음** → 회고에서 겪은 "6/27 데이터" 혼선을 그대로 물려받음. 시작/종료 경계일은 KST 변환 기준으로 정의할 것.
5. **`track()` conversion 고정**(K 피드백): 전환 이벤트가 `conversion`으로 고정 전송되면 `enrollment_completed`/`project_alert_signup` 구분이 안 됨. properties/event_name 필터 가능 여부를 QA 항목에 추가.
6. **도달률 현실화**: 회고 실측 runner 노출률 16.8%(33/196). 이 도달률이면 결정실험화 조건(누적 노출 ≥450/그룹)은 MAU 가정보다 훨씬 오래 걸림 → 탐색 분류 유지 + analysis-plan §6에 "실측 도달률 기준 예상 기간" 추가 권장.

## 5. 구조적 불일치 — 참고

7. **배정 해시 표기 불일치**: experiment-spec `hash(user_id+experiment_id)` / analysis-plan `sha256(experiment_id:uid)` / 실제 코드 `crc32(user_id:flag_key)`(K 확인). 재현성 원칙상 실제 구현으로 통일 기록. flag_key가 null이라 **배정 키 자체가 아직 미정**.
8. **실험 2중 등록 전례**: home_layout·sponsor_slot이 각각 2건 등록됨 — 사이드바 등록 시 중복 생성 주의(SRM 기대비율 혼선 원인).
9. **PLAT-4(Guardrail 훅) 부재 방증**: 모든 실험의 `guardrail_metrics=null`. SNAV-11r 등록 시 guardrail_metrics를 수동으로라도 채울 것.
10. **PLAT-1 상태 재평가**(K 피드백 보강): event_log는 "부재"가 아니라 **부분 가동**(회고 이벤트 적재 중). 단 experiment_id·session_id·variant 계약 미충족이므로 "완료"도 아님 — 백로그 상태를 "부분 가동, 스키마 계약 미충족"으로 갱신 권장.

3. 🔴 **queries.md 개정**: event_name/flag_key 기준으로 재작성, 분모는 `dl_feature_flag_exposure` 기준 검토.
4. 🟡 **SNAV-14 QA**: §6 체크리스트 8항목 전부 ✅ 후 10%→50% 점진 배포. AA 테스트 포함.

## 8. 한계 (정직 표기)

- `dl_event_log`에 `variant` 컬럼의 존재·적재 여부는 **미확인**(사이드바 이벤트가 0건이라 검증 불가).
- session_id·SDK 동작에 관한 실측 근거는 **회고 실험 데이터**다. 사이드바가 같은 SDK를 쓴다는 전제(K 피드백)에 의존하며, 사이드바 전용 경로에서 다를 가능성은 배제 못 함.
- 쿼리 엔진 제약(SELECT만·LIMIT 100·CTE 불가·5초) 하의 집계 쿼리만 사용 — 행 단위 전수 검증은 아님.
- 이 문서는 **초안** — 확정 및 상위 전파(playbook·백로그 갱신)는 검토 승인 후.

## 9. 재현 쿼리 (고정 — 2026-07-13 실행분)

```sql
-- (1) event_log 이벤트별 현황 + null 진단
SELECT experiment_id, event_name, COUNT(*) AS cnt,
  SUM(CASE WHEN session_id IS NULL THEN 1 ELSE 0 END) AS null_session,
  MIN(base_date) AS first_dt, MAX(base_date) AS last_dt
FROM dl_event_log
GROUP BY experiment_id, event_name ORDER BY experiment_id, cnt DESC LIMIT 100
```

```sql
-- (2) 실험 등록 현황 (snapshot → MAX(base_date) 필터 필수)
SELECT id, name, status, flag_key, product, experiment_type, guardrail_metrics
FROM dl_experiments
WHERE base_date = (SELECT MAX(base_date) FROM dl_experiments) LIMIT 20
```

```sql
-- (3) 활성 flag
SELECT flag_key, rollout_pct, enabled FROM dl_feature_flag
WHERE base_date = (SELECT MAX(base_date) FROM dl_feature_flag)
  AND archived_at IS NULL LIMIT 30
```

```sql
-- (4) 노출 테이블 스키마 확인 (session_id 컬럼 없음)
SELECT * FROM dl_feature_flag_exposure LIMIT 2
```

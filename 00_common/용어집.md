# 🔤 용어집 — 처음 보는 분을 위한 해설

> 실험·데이터 문서에 자주 나오는 말을 **일상어 + 비유**로 설명합니다. (두 실험 공용)

## 1. 실험 기본
| 용어 | 쉽게 말하면 | 비유 / 주의 |
|---|---|---|
| **A/B 테스트** | 두 버전을 무작위로 나눠 보여주고 어느 쪽이 더 나은지 비교 | 식당에서 신메뉴 A/B를 손님 절반씩 줘보고 반응 비교 |
| **control (대조군)** | **기존 그대로**인 그룹 | 비교 기준선 |
| **treatment (실험군)** | **바꾼 새 버전**을 받은 그룹 | 우리가 효과를 보고 싶은 쪽 |
| **variant (변형)** | 사용자에게 보여주는 버전(=control 또는 treatment) | 여기선 "현행 사이드바" vs "심플 사이드바" |
| **배정 (assignment)** | 각 사용자를 control/treatment 중 하나에 넣는 것 | 입장할 때 A/B 팔찌 채워주기 |
| **결정적·sticky 배정** | 같은 사람은 **항상 같은 그룹**에 가도록 ID로 계산해 고정 | 한 번 A면 다음에 와도 계속 A (왔다갔다 X) |
| **kill switch** | 문제 생기면 실험을 **즉시 끄고 전원 기존(control)으로** | 비상 정지 버튼 |

## 2. 측정·지표
| 용어 | 쉽게 말하면 | 비유 / 주의 |
|---|---|---|
| **노출 (exposure)** | 사용자가 실험 화면을 **실제로 봤다**는 기록 | 배정만 됐다고 본 게 아님. **비율 계산의 분모 = '본 사람'** |
| **CTR (클릭률)** | 본 사람 중 **클릭한** 사람 비율 (클릭÷노출) | |
| **전환율 (conversion)** | 본 사람 중 **최종 목표(등록 등)까지** 간 비율 | |
| **퍼널 (funnel)** | 노출→클릭→페이지→등록처럼 단계마다 사람이 줄어드는 흐름 | 깔때기. **어디서 많이 빠지나** 보는 것 |
| **Primary KPI** | 성공을 판단하는 **핵심** 지표 | 사이드바: 핵심메뉴 CTR·등록 전환 |
| **Guardrail (가드레일)** | **망가지면 안 되는 안전 지표** | 이게 나빠지면 Primary가 좋아도 **출시 금지** (예: 이탈률↑) |
| **MDE (최소 감지 가능 효과)** | 이 실험으로 잡아낼 수 있는 **최소 차이** | 작은 차이를 잡으려면 표본이 훨씬 많이 필요 |
| **표본 크기 / 검정력(power)** | 결론 내리려면 필요한 **인원 수** | 너무 적으면 차이가 있어도 "있다"고 못 말함 |
| **결정 / 탐색 실험** | 결정=출시 판단 가능(표본 충분) / 탐색=**방향만**(표본 부족) | 사이드바는 현재 트래픽상 **탐색** |

## 3. 통계·판정
| 용어 | 쉽게 말하면 | 비유 / 주의 |
|---|---|---|
| **SRM (Sample Ratio Mismatch)** | 50:50으로 나눴는데 **실제 비율이 이상하게 틀어진 것**(예: 54:46) | 동전 1만 번에 앞면 5400번이면 동전/세는 게 이상. **배정·계측 버그 신호 → 결과 신뢰 불가, 실험 중단** |
| **카이제곱 (chi-square)** | 비율이 기대(50:50)에서 **우연 이상으로** 벗어났는지 따지는 검정 | SRM 판정에 사용 |
| **Bayesian P(T>C)** | "treatment가 control보다 좋을 **확률**"을 %로 표현 | **≥95%면 출시 고려**. p-value보다 직관적 |
| **AA 테스트** | 배포 전 **양쪽에 똑같은 화면**을 줘서 차이가 0으로 나오는지 확인 | 계측·배정이 정상인지 점검(거짓 차이 안 나는지) |
| **4-state 판정** | 실험 결론 4가지: `ship`(출시) / `hold`(보류) / `rollback`(되돌림) / `need_more_data`(데이터 더) | Guardrail 망가지면 ship 불가 |
| **준실험 (quasi-experiment)** | 무작위로 나누지 않고, **사용자가 스스로 고른 그룹**끼리 비교하는 실험 | 회고 실험: "쓴 사람 vs 안 쓴 사람". 원인 단정 불가, **연관 수준까지만** 말할 수 있음 |
| **선택편향 (selection bias)** | 애초에 **다른 종류의 사람들**이 각 그룹에 들어가서 생기는 왜곡 | 새벽반 수강생 성적이 좋다고 새벽반 덕이라 할 수 없음 — **부지런한 사람이 새벽반을 고른 것** |
| **SMD (Standardized Mean Difference, 표준화 평균 차이)** | 두 그룹의 **사전 특성이 얼마나 다른지** 재는 통계 지표. 계산: **(A그룹 평균 − B그룹 평균) ÷ 합동 표준편차** — 단위와 무관해 어떤 지표든 같은 눈금으로 비교 가능. 준실험의 **균형 검사**(선택편향 진단)에 사용 | 달리기 전 출발선 간격 재기. 판정(playbook 3-2): **≤0.1** 균형 → 층화 분석 / **0.1~0.2** → 공변량 보정 회귀 / **>0.2** → 해석 제한 또는 탐색 재분류 |
| **공변량 / 보정 (covariate / adjustment)** | 결과에 영향을 주는 **사전 특성**(예: 원래 출석률)을 계산에 넣어 출발선 차이를 상쇄하는 것 | 골프 핸디캡. 잘 치던 사람과 초보의 점수를 그대로 비교하지 않고 핸디캡을 적용 |

## 4. 데이터·엔지니어링
| 용어 | 쉽게 말하면 | 비유 / 주의 |
|---|---|---|
| **variant 프론트 연동** | 사용자가 **어느 버전(variant)에 배정됐는지 받아, 그 버전 화면을 실제로 그려주는** 프론트엔드 작업 | "이 사람한텐 A, 저 사람한텐 B 보여줘"를 코드로. + 본 순간 '노출' 기록 |
| **event_log** | 사용자 행동(봄·클릭·등록)을 **한 줄씩 쌓는 기록 테이블** | 모든 분석의 원천 |
| **적재 (ingest)** | 데이터를 테이블에 **집어넣는 것** | |
| **incremental 적재** | 행마다 **한 번 쌓고 끝** (중복 없음) | 이벤트성 데이터 |
| **snapshot 적재** | **매일 전체 상태를 다시 찍어** 쌓음 | 날짜 필터(`base_date`/`as_of_date`=MAX) 안 하면 **수십 배 중복** |
| **멱등 적재 (idempotent)** | 같은 데이터를 **두 번 보내도 한 번만** 저장 | 재전송해도 안전 |
| **PK / FK** | PK=각 행의 고유 번호 / FK=다른 표를 가리키는 연결 키 | `user_id`·`project_id` 등 |
